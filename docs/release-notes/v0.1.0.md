# RTSPS Secure 0.1.0

First public prerelease of **RTSPS Secure**, an experimental OBS Studio source
that receives RTSPS video and audio with exact TLS certificate pinning.

## Downloads

| File | Purpose |
| --- | --- |
| `rtsps-secure-0.1.0-windows-x64-setup.exe` | Windows x64 installer; requires administrator rights and OBS closed |
| `rtsps-secure-0.1.0-windows-x64.zip` | Manual installation; contains the `rtsps_secure` plugin folder |
| `SHA256SUMS.txt` | SHA-256 checksums for both packages |

Verify downloads before running them:

```powershell
Get-FileHash .\rtsps-secure-0.1.0-windows-x64-setup.exe -Algorithm SHA256
```

The installer is **not code-signed**, so Windows may show an unknown-publisher
warning.

## Requirements

- 64-bit Windows
- OBS Studio 33.x, 64-bit
- A camera that supports RTSPS and interleaved RTSP over TCP
- A PEM file containing the camera's exact server certificate

## What is included

- Rust TLS bridge with exact leaf-certificate pinning.
- Certificate validity and TLS handshake signature checks.
- Manual certificate discovery with SHA-256 fingerprint confirmation.
- Video and audio through OBS's built-in media source.
- Installer backup and clean uninstall behavior.

## Tested scope

Windows x64 with OBS Studio 33.0.1 was tested with a synthetic RTSPS stream and
an Android IP Camera. Tests covered certificate discovery and approval, repeated
GUI button clicks, invalid URLs, mismatched certificates, audio/video delivery,
settings changes, and clean OBS shutdown.

Linux and macOS are **compile-only experiments** in CI. No Linux, Flatpak, or
macOS package is included.

## Security limitations

- First-use certificate discovery does not authenticate the camera. Verify the
  fingerprint independently before approving it.
- OBS receives decrypted RTSP on a loopback port that other local processes may
  access.
- Camera credentials are not supported. Do not put secrets in URLs.
- This project has not received an independent security audit.
